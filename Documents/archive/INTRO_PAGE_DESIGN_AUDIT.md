## 1. 결론

현재 Intro 페이지는 제공 기능을 충분히 보여주지만, **제품을 빠르게 이해시키는 랜딩 페이지보다 기능을 길게 나열한 소개 자료에 가깝다.** Dark Navy와 Blue 계열은 제품 내부와 연결되지만, Blue/Violet/Pink glow, 배경 orb, gradient text, 3D 로봇, 떠오르는 카드와 반복 애니메이션이 한 화면에 겹쳐 전형적인 AI SaaS 템플릿 인상을 만든다.

가장 큰 문제는 이미지 수가 아니라 다음 세 가지다.

1. Hero에서 제품의 정체성·차별점·실제 화면이 즉시 증명되지 않는다.
2. 목적, 기능 카드, 서사 카드, 상세 기능이 비슷한 내용을 반복해 페이지가 지나치게 길다.
3. 장식용 효과와 3D 이미지의 비중이 커서 실제 업무 도구가 가진 신뢰성과 정밀함이 약해 보인다.

추천 방향은 **Calm Product-led Technical Landing**이다. 실제 제품 화면을 주 시각 자료로 사용하고, Graphite 계열 표면과 제한된 Blue accent, 명확한 타이포그래피, 얇은 경계선, 작은 반경, 정적인 기술 다이어그램으로 제품의 전문성을 보여준다.

## 2. 현재 페이지 구조

현재 화면은 아래 순서로 구성된다.

1. Hero 카피, CTA, YouTube 영상
2. 서비스 제작 목적과 대상 사용자
3. 연동 서비스 무한 marquee
4. 기능 설명 Bento 카드 6개
5. 2.5D 서사 일러스트 3개

375줄의 JSX와 1,106줄의 전용 CSS로 단일 랜딩 페이지치고 구현 규모가 크다. 위계가 다른 섹션이 많지만 배경색과 카드 문법이 유사해, 실제로는 긴 하나의 어두운 화면처럼 읽힐 가능성이 높다.

## 4. 정보 구조 문제

### 4.1 Hero가 답하지 못하는 질문

현 Hero의 “코딩 없이 연결하는 시각적 업무 자동화”는 제품군은 설명하지만 아래 질문에는 답하지 못한다.

- 어떤 업무를 가장 잘 자동화하는가?
- 국내 환경에 맞췄다는 것이 구체적으로 무엇인가?
- 다른 워크플로우 도구와 비교해 왜 이 제품을 선택해야 하는가?
- 생성된 자동화가 안전하게 실행되는지 어떻게 확인하는가?

차별점인 한국어 생성, 국내 연동, 승인, 실행 관찰 기능은 첫 화면 이후 여러 섹션으로 흩어져 있다. Hero에는 가치 제안, 실제 편집 장면, 한 개의 주 CTA와 한 개의 저위험 보조 CTA가 함께 있어야 한다.

### 4.2 설명의 반복

다음 섹션들이 역할을 명확히 나누지 못한다.

- “왜 만들었나요?”: 문제 정의
- “무엇을 할 수 있나요?”: 활용 사례
- “업무의 흐름을 더 선명하게”: 제품 원칙
- Major feature 3개: 기능 설명

각 구간의 문장은 다르지만 자동화 연결, AI 처리, 모니터링이라는 같은 세 축을 반복한다. 권장 구조는 아래처럼 축소할 수 있다.

```text
Header
  → Hero + 실제 제품 동작
  → 대표 활용 흐름 3개
  → 핵심 제품 능력: 생성 / 제어 / 관찰
  → 실제 사용 3단계
  → 신뢰·보안·연동 근거
  → CTA + Company footer
```

### 4.3 전환 동선 부족

- 상단에 로그인이나 기존 사용자 진입 경로가 없다.
- CTA가 “무료로 시작하기” 한 종류뿐이라, 제품을 더 확인하려는 방문자의 선택지가 없다.
- 영상은 큰 영역을 차지하지만 “영상 보기”가 CTA 계층에 포함되지 않고 포스터 자체를 눌러야 한다.
- 문서, 템플릿, 튜토리얼처럼 이미 구현된 저위험 탐색 경로를 활용하지 않는다.

## 5. 시각 디자인 문제

### 5.1 “AI 느낌”을 만드는 요소

개별 요소가 나쁜 것은 아니지만 아래 표현을 동시에 사용해 상용 템플릿 인상이 강해진다.

- Blue/Violet gradient headline
- Blue, Violet, Pink 대형 blur orb 3개
- Hero radial glow와 이미지 glow
- 카드 내부 radial glow
- 50px pill CTA와 강한 파란 shadow
- hover 시 카드 상승, 아이콘 확대와 회전
- 2.5D 무광 로봇 캐릭터 3장
- fade-up, marquee, step highlight, orb floating의 동시 사용

현대적인 IT 기업의 인상은 효과의 수보다 **정렬, 타이포그래피, 실제 제품 정보, 일관된 간격과 절제된 상호작용**에서 만들어져야 한다.

### 5.2 구간 대비 부족

대부분의 구간이 `var(--bg-color)` 또는 `var(--card-bg)` 위에 같은 border와 radius를 사용한다. 섹션 간 여백은 크지만 명도·레이아웃·콘텐츠 밀도 변화가 작아 긴 페이지의 리듬이 약하다.

개선 시에는 배경색을 계속 바꾸기보다 다음 수단을 제한적으로 사용한다.

- full-bleed 제품 화면 구간
- 좁은 텍스트 중심 구간
- 2열 설명 구간
- 얇은 grid/rule로 나뉜 기술 사양 구간
- 한 번만 사용하는 accent surface

### 5.3 형태 언어가 제품 UI와 다름

제품 내부는 작은 반경, 얇은 border와 조밀한 toolbar가 강점이다. Intro는 20px 카드, 50px pill, 큰 shadow가 중심이라 제품과 연결되지 않는다. Landing에서도 제품과 같은 8~12px 반경, border 중심 elevation, Blue primary button을 사용해야 브랜드 전환이 자연스럽다.

### 5.4 타이포그래피와 카피 톤

- Hero 첫 줄 `45px`이 JSX inline style로 고정돼 반응형 체계를 깨뜨린다.
- `<br style={{ fontSize: '70x' }}>`는 유효하지 않은 값이며 의미가 없다.
- 긴 설명문에 `<br /><br />`로 문단을 만들고 있어 콘텐츠 폭 변화에 유연하지 않다.
- “얼마나 좋을까?”, “놀랄만큼 강력”, “당신의 훌륭한 AI 비서”는 전문 B2B 도구보다 홍보 문구에 가깝다.
- 특정 모델명은 빠르게 오래된 정보가 되므로 실제 지원 목록과 자동 연동되지 않는 한 제거하는 편이 안전하다.

### 신규 이미지가 필요한가?

**P0 개편에는 신규 생성 이미지가 필요하지 않다.** 새 이미지를 더 넣기 전에 현재 제품 화면을 최신 상태로 다시 캡처하고, 핵심 동작만 잘 보이도록 crop하는 편이 신뢰성과 정보 전달력이 높다.

신규 생성 이미지는 다음 조건에서만 제한적으로 고려한다.

1. Hero 뒤에 사용할 매우 절제된 추상 workflow texture 1장
2. 국내 연동이나 사용자 승인처럼 실제 UI만으로 설명하기 어려운 개념 장면 1장
3. OG·공유 카드처럼 제품 페이지 본문과 분리된 마케팅 자산

생성할 경우에도 캐릭터 중심 3D 장면보다 평면에 가까운 기하학 구성, 단색 배경, 큰 형태 2~4개, 무문자, glow 없는 스타일을 우선한다. 기존 Nodi는 온보딩·완료·도움말처럼 정서적 맥락이 필요한 곳에 남기고, 제품 설명의 주 시각 언어로 확대하지 않는다.

## 7. 반응형·접근성·성능 문제

### 반응형

- Hero의 inline `45px`이 768px·480px breakpoint보다 우선한다.
- 제품 전체 화면 이미지는 모바일에서도 그대로 축소되어 세부 정보를 읽기 어렵다.
- 992px, 768px, 480px breakpoint가 제품 디자인 문서의 권장 1200px, 900px, 600px 체계와 다르다.
- 모바일에서 상단 Header가 없어 현재 위치와 다음 행동을 제공하지 못한다.

### 접근성

- `prefers-reduced-motion` 대응이 없어 orb, marquee, step highlight가 계속 움직인다.
- `.fade-up-element`는 기본 `opacity: 0`이므로 IntersectionObserver 실행 실패 시 주요 콘텐츠가 보이지 않을 수 있다.
- marquee가 7개 항목을 6회 반복 렌더링하며 장식 복제본을 보조 기술에서 숨기지 않는다.
- CTA와 hover 상태는 있으나 공통적인 `focus-visible` 처리가 영상 버튼 외에는 부족하다.
- 의미상 Footer가 `<section>`으로 작성되어 페이지 landmark가 약하다.

### 성능

- Demo WebP 3개의 합계가 약 4.1MB이며 모두 초기 JSX에 포함된다.
- 42개 marquee 항목, 다수 blur filter, fixed orb와 연속 애니메이션이 저사양 모바일의 합성 비용을 높일 수 있다.
- 모든 fade 대상에 `will-change`가 계속 적용돼 불필요한 레이어 메모리를 사용할 수 있다.
- 영상 iframe은 클릭 후 로드하는 현재 방식이 적절하므로 유지 가치가 있다.

## 10. 완료 판단 기준

- 첫 화면만 보고 제품의 입력, 처리 방식과 결과를 설명할 수 있다.
- 10초 안에 시작하기, 제품 보기, 문서 보기 중 원하는 행동을 선택할 수 있다.
- 페이지 주요 섹션이 6개 이내이며 같은 가치 제안을 반복하지 않는다.
- 실제 제품 화면이 장식 이미지보다 먼저, 더 크게 보인다.
- 3D 캐릭터 이미지는 페이지 전체에서 최대 1개만 주요 노출된다.
- Primary Blue 이외의 색은 상태 또는 작은 강조에만 사용된다.
- 390px 화면에서 Hero 제목, CTA와 제품 화면에 가로 overflow가 없다.
- `prefers-reduced-motion`에서 지속 애니메이션이 중지된다.
- Dark/Light theme 모두에서 본문과 제목 대비가 유지된다.
- 신규 랜딩 이미지가 없어도 완성된 화면으로 보인다.

## 11. 최종 판단

현재 Intro의 다음 개선은 **이미지 추가가 아니라 감산 편집**에서 시작해야 한다. 장식 효과와 반복 설명을 줄이고 실제 제품 동작을 확대하면 AI 생성 느낌은 자연스럽게 줄어든다. 신규 GPT 이미지는 제품이 설명하지 못하는 단 하나의 개념을 보완할 때만 사용하고, 랜딩의 주인공은 제품 UI와 구체적인 업무 결과가 되어야 한다.

2026-08-28에 제품 증거와 신뢰 구간을 적용했다.

- 사용자 승인, 실행 전 문제 검사, 노드별 실행 상태·로그, API 센터 암호화·마스킹을 실제 구현 범위에 맞춰 설명

- 특정 AI 모델명과 “완벽하게”, “정확히” 같은 빠르게 낡거나 과장된 문구 제거

### Slice 4 적용 상태

2026-08-28에 품질과 유지보수 정리를 적용했다.

- `prefers-reduced-motion`에서는 등장·전환 애니메이션을 중단하고, IntersectionObserver가 동작하지 않아도 콘텐츠가 기본 노출되도록 처리
- 모든 링크·버튼에 공통 `focus-visible` 표시를 적용하고 Header, Main, Footer landmark와 탐색 레이블 정리
- 무한 marquee와 복제 항목을 제거하고 실제 연동 목록을 정적인 리스트로 제공
- Hero 외 Demo는 lazy loading, 모든 Demo는 비동기 decoding과 고정 intrinsic 크기를 지정해 초기 네트워크 비용과 layout shift를 줄임
- 사용하지 않는 orb·glow·3D 서사·marquee CSS와 import를 제거하고 활용 사례·기능·단계·신뢰 항목을 데이터 구조로 분리
- 반응형 기준을 1200px, 900px, 600px 세 구간으로 통일

기존 Demo 3개는 합계 약 4.06MB(`demo-1` 1.53MB, `demo-2` 1.07MB, `demo-3` 1.47MB)다. 이미 손실 압축된 구형 시연을 다시 압축해 글자 가독성을 떨어뜨리지 않고, 위의 재녹화 규격으로 교체하는 것을 최종 용량 최적화 기준으로 삼는다. 따라서 코드 수준의 지연 로딩·레이아웃 안정화는 완료됐고, 바이너리 용량 교체만 신규 시연 파일 수급 후 남는다.
