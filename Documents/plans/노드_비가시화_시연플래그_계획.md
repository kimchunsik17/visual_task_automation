## 목적

시연에서 "많지만 일부 미완성"보다 "적지만 전부 동작"이 안전하다. 미완성 노드를 삭제하지 않고, 환경변수 토글 하나로 사용자에게 보이는 모든 표면에서 감춘다. 시연이 끝나면 환경변수 제거로 원상 복구된다.

## 핵심 원칙

1. **하드코딩 삭제 금지** — 노드 정의·생성기·테스트는 그대로 둔다. 숨김은 조회 시점 필터다.
2. **기존 워크플로우는 계속 실행된다** — 숨긴 노드가 이미 놓인 프로젝트·템플릿의 실행 경로는 건드리지 않는다. 시연용으로 미리 만든 워크플로우가 깨지지 않아야 한다.
3. **표면 3곳을 전부 막아야 한다** — 팔레트 한 곳만 막으면 자연어 생성이 뚫는다(아래 참조).

## 노드가 사용자에게 노출되는 표면 3곳

| # | 표면 | 위치 | 왜 막아야 하는가 |
| --- | --- | --- | --- |
| 1 | 에디터 팔레트·삽입/교체 후보 | `frontend/src/editorNodeCatalog.js` `STATIC_EDITOR_NODES`, `EDITOR_NODE_CATALOG.filter(...)` | 드래그 추가 차단. 가장 눈에 띄는 표면 |
| 2 | 자연어 생성 에이전트 | `backend/node_definition.py` `definitions_payload()` · `inject_catalog_entries()` — LLM 프롬프트에 노드 카탈로그 주입 | **최대 위험 지점.** 시연 2층의 하이라이트가 자연어→그래프 생성인데, 프롬프트 카탈로그에 남아 있으면 방문자 요청에 따라 생성 에이전트가 미완성 노드를 그래프에 넣는다 |
| 3 | 커뮤니티 템플릿 갤러리 | 템플릿 검색·설치 경로 (`backend/community_templates.py`) | 숨긴 노드를 쓰는 템플릿이 검색·설치되면 표면 1·2를 막은 의미가 없다. 노드 목록 기준 필터링 필요 |

## 선례 — `/api/features`의 `python_node_enabled`

`backend/main.py:1141` `/api/features`에 이미 같은 패턴이 있다:

> 꺼져 있으면 편집기가 팔레트에서 pythonNode 를 빼야 한다. 실행 경로는 이 값과 무관하게 서버에서 다시 막으므로, 이건 UI 가 헛수고를 안 하게 하는 힌트다.

이 단일 노드용 플래그를 목록으로 일반화한다. 단, python_node와 달리 시연 숨김 노드는 **실행을 서버에서 막지 않는다**(원칙 2 — 기존 워크플로우 보호).

## 설계

### 백엔드

```
HIDDEN_NODE_TYPES=nodeA,nodeB   # 환경변수, 미설정 시 빈 목록 (= 현행과 동일)
```

- `/api/features` 응답에 `hidden_nodes: ["nodeA", "nodeB"]` 추가.
- `definitions_payload()` · `inject_catalog_entries()`가 목록에 있는 타입을 제외한다 → 생성 에이전트 프롬프트에서 사라짐.
- 커뮤니티 템플릿 목록/검색 API가 숨긴 노드를 포함하는 템플릿을 제외한다(이미 설치된 프로젝트는 무관).
- 존재하지 않는 노드 타입이 목록에 있으면 기동 시 경고 로그(오타 방어).

### 프론트엔드

- 앱 초기화 시 `/api/features`를 한 번 조회(현재 `DatabaseQueryPanel.jsx:36`의 개별 조회를 공용 훅/모듈로 승격하는 것을 권장).
- `editorNodeCatalog.js`의 카탈로그 조회 함수가 `hidden_nodes`를 필터 — 팔레트, 노드 교체 후보, 튜토리얼/문서 목록에 일괄 반영.
- 캔버스에 이미 놓인 숨김 노드는 정상 렌더·정상 실행(원칙 2).

### 적용·복구 절차

1. 시연 전: 숨길 노드 목록 확정 → 해당 노드를 쓰는 커뮤니티 템플릿 수를 조회해 갤러리 영향 확인 → 환경변수 설정 → 재기동.
2. 시연 후: 환경변수 제거 → 재기동. 코드 변경 없음.

## 시연 공유 자격증명 (구현 완료 · 2026-09-03)

부스에서는 방문자가 승인키를 그 자리에서 발급받을 수 없다. 두 환경변수가 모두 설정된
동안, **자격증명이 없는 사용자의 실행에 한해** 부스 계정의 API 센터 키를 대신 쓴다.

```
DEMO_SHARED_CREDENTIALS_USER_ID=<부스 계정 user id>
DEMO_SHARED_CREDENTIALS_PROVIDERS=juso,data_go_kr
```

구현(`backend/demo_credentials.py`):

- **커넥터 경로**: `connectors.oauth.require_token` — 모든 공식 연동 노드의 단일 관문.
  사용자 키가 없고 provider 가 허용 목록에 있으면 부스 계정 키로 해석한다.
- **placeholder 경로**: `graph.run_workflow` 의 `{{API_CENTER:*}}` 치환 맵 — 소유자에게
  없는 허용 provider 를 폴백으로 채우고, 실제로 치환에 쓰인 것만 기록한다.
- **기록**: 사용될 때마다 서버 로그 한 줄 + `flow_execution_logs` 에
  `event_type="demo_credential_use"` 한 행(실행자·프로젝트·provider — 비밀 값 없음,
  토큰 차감 없음, billable 은 부스 계정으로 모아 집계). 조회:
  `SELECT * FROM flow_execution_logs WHERE event_type='demo_credential_use';`
- **원칙**: 기본 꺼짐(변수 제거 = 원상 복구) · 사용자 본인 키 우선 · mock 실행은 폴백 이전에
  기존대로 단락됨 · **OAuth 형(kakao_token·gmail 등)은 목록에 넣지 말 것** — 공개 데이터
  API(juso·data_go_kr)처럼 유출 피해가 작은 키만 공유한다.
- 재발 방지: `backend/test_demo_credentials.py` (게이트·우선순위·허용 목록·기록·비밀 미기록).

## 시연장 로그인 (구현 완료 · 2026-09-03)

부스 노트북 3대는 새 기기라 구글 로그인이 추가 인증에 막히기 쉽다. 아래 변수가 설정된
동안에만 로그인 화면에 "시연 로그인" 입구가 열린다 (`POST /api/auth/demo`).

```
DEMO_LOGIN_CODE=<부스 공유 코드>      # 설정 = 켜짐, 제거 = 닫힘
DEMO_LOGIN_SEATS=3                    # 좌석 수 (기본 3, 최대 10)
```

- 코드(hmac 상수시간 비교)가 맞으면 좌석별 계정(`demo-booth-N`, `boothN@demo.local`,
  "시연 N번 좌석")으로 7일짜리 JWT 를 발급한다. 같은 좌석은 항상 같은 계정 — 재로그인해도
  작업물이 유지된다. 데모 계정은 일반 사용자다(admin 아님).
- 프론트: /api/features 의 `demo_login`/`demo_login_seats` 가 켜졌을 때만 로그인 영역에
  좌석 선택 + 코드 입력이 그려진다(MainSidebar).
- 시연 콘텐츠(seed_demo_booth.py)는 대표 시연 계정에 심고, 좌석 계정은 층 2 "방문자가
  직접 만들어보기"용으로 쓴다. 좌석 계정에도 콘텐츠가 필요하면 `--email boothN@demo.local`
  로 시드를 추가 실행하면 된다.
- 재발 방지: `backend/test_demo_login.py` (게이트 404·코드 401·좌석 422·계정 재사용·토큰 인증).

## 시연 게스트 입장 (구현 완료 · 2026-09-04)

부스 방문자가 계정 없이 바로 체험한다 — 접속하면 자동으로 게스트 계정에 들어가고,
시연 콘텐츠(워크플로우 5종 + 앱 2종 + 전용 포맷 2종)가 그 계정으로 복사된다.

```
DEMO_GUEST=1            # 설정 = 켜짐, 제거 = 원상 복구
DEMO_GUEST_TOKENS=50000 # 게스트 1명당 토큰 (기본 5만, 1천~200만) — 소진 시 실행 차단
DEMO_GUEST_MAX=300      # 게스트 계정 총량 상한 (기본 300) — 무인증 입구의 행 폭주 방어
```

- `POST /api/auth/guest`: 방문자마다 별도 계정(`demo-guest-<uuid>`, `guest-…@demo.local`)을
  만들고 3일짜리 JWT 를 발급한다. **게스트별 토큰 상한**이 크레딧 폭주를 막는다 — 기존
  `token_balance <= 0` 실행 게이트가 그대로 작동하고, 모자라면 어드민 패널(사용자 목록 →
  토큰 설정, `PUT /api/admin/users/{id}/token`)에서 충전한다.
- **콘텐츠 복사**: seed_demo_booth.seed(validate=False) 를 게스트 계정에 실행 — 포맷 id 는
  소유자별(`demo-travel-itinerary-u<id>`)로 나뉜다(DocumentFormat.id 가 PK + 소유자 검증).
  시딩이 실패해도 입장은 된다(빈 계정).
- **관리자 예외**: 구글 로그인은 그대로. 프론트 자동 입장(AuthContext)은 "명시적 로그아웃"
  뒤에는 멈춘다(sessionStorage `wf-demo-guest-optout`, 탭 단위) — 로그아웃하면 구글 로그인
  버튼과 "게스트로 입장하기" 버튼이 함께 보인다.
- 재발 방지: `backend/test_demo_guest.py` (게이트 404·토큰 상한·콘텐츠 복사·게스트 분리·정원 429).
