## 1. 왜 지금 하는가

2026-08-28에 App Builder 의 기능이 크게 늘었다 — 컴포넌트 16종, 되돌리기, 정렬·분배, 계층
숨김, onChange 트리거. 기능이 늘수록 지금 화면의 문제가 더 드러난다.

- 헤더에 색이 다른 버튼 9개가 한 줄에 놓여 "무엇을 먼저 눌러야 하는지"가 안 보인다.
- 속성 패널이 항목 40여 개의 긴 목록이 되어 스크롤 없이는 원하는 속성을 못 찾는다.
- 다크 색이 코드에 박혀 있어(인라인 style 51곳, hex 40곳) 라이트 테마에서 헤더·팝오버·캔버스
  배경이 어긋난다.
- 워크플로우 에디터와 같은 회사의 제품이라고 보기 어렵다 — 헤더, 아이콘 버튼, 패널 문법이 다르다.

상위 감사 문서가 Phase 4 로 잡아둔 일이지만, 지금 App Builder 를 실제로 쓰는 흐름이 생겼으므로
전체 디자인 시스템 완성을 기다리지 않고 **App Builder 안에서 먼저 정리**한다. 단, 나중에 전역
토큰·공통 Primitive 가 오면 한 줄 alias 로 갈아탈 수 있게 만든다(§5.1).

## 2. 현재 상태 감사

코드를 기준으로 한 감사다(스크린샷은 실행 환경이 필요해 생략). 줄 번호는 2026-08-28 기준.

### 2.1 헤더 — 우선순위가 없다

```text
[←][커서 아이콘][앱 이름][ⓘ] [Code Native|Blueprint]   [Design|Blueprint|Preview|Code|Global CSS]   [로그][AI 어시스턴트][저장 및 배포]
   amber/violet 세그먼트                 blue  violet   green   pink  amber                          violet  green
```

- **생성 방식 세그먼트(Code Native / Blueprint)** 가 헤더에 있고, 값에 따라 View 탭(Blueprint 또는
  Code)이 **나타나고 사라진다**. 사용자가 보기엔 "탭이 어떤 때는 있고 어떤 때는 없는" 화면이다.
  이 값은 사실 AI 에게 "로직을 어떤 형태로 생성할지" 알려주는 옵션이다 — 헤더가 아니라 AI
  어시스턴트의 옵션 자리(이미 "Workflow 연결" 세그먼트가 있다)에 있어야 한다.
- View 탭 5개가 **각각 다른 색**(blue/violet/green/pink/amber)으로 활성 표시된다. 색이 의미(성공·
  위험·AI)가 아니라 장식으로 쓰인다 — 감사 문서 §5.2 위반.
- Primary CTA 가 둘이다: "저장 및 배포"(green)와 AI 어시스턴트(violet 테두리). 게다가 배포 버튼이
  저장을 겸하는데 이름이 길어 "저장만" 하고 싶은 사용자가 망설인다.
- 헤더 좌측에 장식 아이콘(`MousePointer2`, blue)이 있다 — 정보가 없다.

### 2.2 색 — 하드코딩과 장식적 사용

| 위치 | 현재 | 문제 |
| --- | --- | --- |
| 캔버스 워크스페이스 배경 | `#0f172a` 인라인 | 라이트 테마에서도 검다 |
| 앱 정보 팝오버, 배포 모달, 토큰 배지 | `#111827`, `#0b1220`, `#1e293b` 고정 | 테마와 분리됨(감사 §3.2 지적 그대로) |
| 헤더 세그먼트 배경 | `#0f172a`, `#1e293b` 인라인 | 같음 |
| 실행 로그 패널 | `#111318`, `#191c23` | 터미널 성격이라 다크 유지는 타당하나 토큰이 아니다 |
| Blueprint 팔레트 항목 | 노드별 색 테두리 5종 | 노드 카테고리 색은 아이콘 타일·핸들에만(§5.2) |
| Blueprint 안내 박스 | `rgba(255,255,255,0.05)` | 라이트에서 보이지 않음 |
| 삭제 버튼 | `.btn-danger` 전체 폭, 빨강 테두리 | 파괴적 행동이 패널에서 가장 큰 요소 |

인라인 `style={{ }}` 51곳, hex 색 40곳(가장 많은 것: `#10b981` 8, `#f59e0b` 7, `#0f172a` 5).

### 2.3 패널 — 폭·밀도·위계

- 좌측 팔레트 250px + 안쪽 여백 1.5rem, 항목 높이 ~40px. 계층 트리는 `max-height: 250px` 고정이라
  컴포넌트가 10개를 넘으면 트리 안에서 또 스크롤한다. 팔레트(16개)와 트리가 세로 공간을 다툰다.
- 우측 속성 패널 300px. 선택한 컴포넌트의 속성이 **한 층의 긴 목록**이다 — 텍스트 → 입력 →
  Layout & Size → Design(8개) → Layout Mode → Click Action → Binding → Arrange → 삭제. 접기가
  없고, 같은 성격(굵기/정렬/색)이 흩어져 있다.
- 라벨이 영어("Text Content", "Width")와 한국어("파일 종류", "여러 줄로 줄바꿈")가 섞여 있다.
- 섹션 제목 `.sidebar-title` 이 대문자 + letter-spacing 1px 이다. 감사 §5.3: 대문자 영문 Label 은
  짧은 Category 표시에만.
- 필드 높이가 제각각(0.5rem padding + 글꼴 크기에 의존). 감사 §5.4: compact 32px / default 40px.

### 2.4 캔버스

- 흰 아트보드 + 검은 워크스페이스는 좋은 대비다. 다만 아트보드의 **크기 정보가 화면에 없다** —
  프리셋(Desktop/Tablet/Mobile)은 아무것도 선택하지 않았을 때의 우측 패널 깊숙이 있다.
- 빈 상태는 점선 박스 + 한 문장. 공통 `EmptyState`(일러스트 + 제목 + 설명 + 행동 1개)를 이미
  다른 화면이 쓴다.
- 미리보기 탭이 편집 탭과 똑같은 워크스페이스 위에 같은 크기로 그려져 "지금 편집 중인지 미리보기
  중인지"가 탭 색으로만 구분된다.

### 2.5 다중 선택

정렬·분배·크기 도구가 우측 패널 안에 있다. 워크플로우 에디터는 같은 일을 **캔버스 아래 떠 있는
선택 툴바**(`.editor-selection-toolbar`)로 한다 — 시선이 캔버스에서 떠나지 않는다. 같은 제품의
같은 동작은 같은 자리에 있어야 한다(감사 §6.2).

### 2.6 모바일

`max-width: 900px` 에서 헤더만 줄이고 **3열 레이아웃은 그대로** 유지된다. 390px 에서는 팔레트
250px + 속성 300px 이 화면을 넘어 캔버스가 사실상 사라진다. 감사 문서 §12 가 "가장 큰 사용성
문제"로 첫 구현 범위에 넣은 항목이다.

### 2.7 접근성·모션

- `:focus-visible` 스타일이 없다. 키보드로 탭 이동하면 어디에 있는지 보이지 않는다.
- 아이콘 버튼의 hover 색이 보라(`#a78bfa`)다 — AI 가 아닌 버튼(로그, 되돌리기)에도 AI 색이 쓰인다.
- 오류·안내가 `alert()` 다(실행 실패, 핸들러 없음 등 7곳). 실행 로그 패널이 이미 있으니 그쪽으로
  모을 수 있다 — 이번 범위에서는 문구만 정리하고 토스트는 후속.

### 2.8 유지해야 할 것

- Palette / Canvas / Inspector 3열 데스크톱 구조 — 제작 도구의 표준이다.
- 흰 아트보드와 어두운 워크스페이스의 대비, 자유 배치(Rnd)와 Shift 스냅.
- 실행 로그를 하단 패널로 분리한 것, AI 어시스턴트가 공용 드로어(`AIAssistantDrawer`)인 것.
- Blueprint 노드의 카테고리 색 구분(감사 §11: 익숙한 노드 색을 한 번에 바꾸지 않는다).

## 3. 원칙

상위 문서 §5.1 "Calm Technical Workspace" 를 App Builder 에 맞게 옮긴다.

1. **한 화면에 Primary 는 하나** — "배포". 저장은 아이콘 버튼(에디터와 같은 자리·모양), AI 는
   에디터와 같은 토글 버튼.
2. **색은 의미로만** — Blue 선택·주요 행동, Violet AI 식별, Green 배포 완료, Red 파괴적 행동,
   Amber 확인. View 탭은 중립색, 활성만 Blue.
3. **워크플로우 에디터와 같은 문법** — Tool Header(뒤로 / 정체 / View / 저장 상태 / AI / 실행·배포),
   36px 아이콘 버튼, 플로팅 선택 툴바, 팝오버·필드 스타일은 에디터의 클래스를 **그대로 가져다
   쓴다**(`editor-icon-button`, `project-title-btn`, `editor-project-popover`, `editor-field-input`).
   새 클래스를 만들지 않는 것이 통합의 가장 빠른 길이다.
4. **토큰 없이 색을 쓰지 않는다** — 새 CSS 에 hex 를 직접 쓰지 않는다. 전역 토큰이 아직 없는
   것(surface 단계, semantic 색)은 App Builder 범위 토큰으로 두고 전역이 생기면 alias 한다.
5. **Inspector 는 섹션으로** — 내용 / 배치 / 스타일 / 동작 / 정렬. 접을 수 있고, 마지막 상태를
   기억한다.
6. **캔버스 위를 상시 가리는 것은 없다** — 도구는 선택했을 때만 나타난다.
7. **모바일은 축소판이 아니다** — 한 번에 한 pane.

```text
│ 레이아웃      │ │ ┌──────────────────────────────────────────────┐ │ │ button-3-…  👁 ⧉ │
```

- 생성 방식(Blueprint / Code Native)은 AI 어시스턴트 드로어의 옵션 영역으로 이동한다. View 탭
  4개는 **항상** 보인다(로직·코드 둘 다 사용자가 쓸 수 있는 도구다).
- 코드 뷰 안에 `Global JS | Global CSS` 서브탭을 둔다(헤더 탭 5 → 4).
- 앱 정보(제목·설명)는 에디터처럼 **제목 버튼을 눌러 여는 팝오버**로 통합한다 — 별도 ⓘ 버튼 제거.
- 모바일(≤ 900px): 하단 pane 전환 바 `[컴포넌트] [캔버스] [속성]`. 한 번에 하나만 보인다.

## 5. 세부 설계

### 5.1 토큰

`AppBuilderPage.css` 의 `.builder-layout` 에 범위 토큰을 선언하고, 모든 색을 여기서 가져온다.
전역 semantic 토큰(`--color-*`)이 도입되면 이 블록의 값만 alias 로 바꾼다.

| 토큰 | Dark | Light | 용도 |
| --- | --- | --- | --- |
| `--ab-bg` | `var(--bg-color)` | 〃 | 워크스페이스(캔버스 뒤) 배경 |
| `--ab-surface-1` | `var(--card-bg)` | 〃 | 헤더, 패널 |
| `--ab-surface-2` | `color-mix(card-bg 70%, bg-color)` | `#f0f3f7` | 필드, 팔레트 항목, 서브 영역 |
| `--ab-surface-3` | `rgba(255,255,255,.06)` | `rgba(15,23,42,.05)` | hover, 선택 배경 |
| `--ab-border` | `var(--border-color)` | 〃 | 경계선 |
| `--ab-border-strong` | `color-mix(border 60%, text-muted)` | 〃 | 필드 hover, 구분이 필요한 경계 |
| `--ab-text` / `--ab-text-muted` | `var(--text-color)` / `var(--text-muted)` | 〃 | 본문 / 보조 |
| `--ab-accent` / `--ab-accent-soft` | `var(--primary-color)` / `rgba(59,130,246,.14)` | 〃 | 선택, 활성 탭, 링크 |
| `--ab-ai` / `--ab-ai-soft` | `#a78bfa` / `rgba(167,139,250,.14)` | `#7c3aed` / `rgba(124,58,237,.12)` | AI 식별만 |
| `--ab-success` / `--ab-warning` / `--ab-danger` | `#34d399` / `#fbbf24` / `#f87171` | `#168a61` / `#b66a00` / `#d92d20` | 상태 |
| `--ab-artboard` | `#ffffff` | `#ffffff` | 아트보드(앱 배경은 사용자 rootStyle) |
| `--ab-grid` | `rgba(148,163,184,.18)` | `rgba(71,85,105,.16)` | 워크스페이스 점 격자 |
| `--ab-focus` | `0 0 0 2px var(--ab-bg), 0 0 0 4px var(--ab-accent)` | 〃 | focus-visible 링 |
| `--ab-radius-control` / `-panel` / `-modal` | 6 / 8 / 12px | 〃 | 감사 §5.4 |
| `--ab-field-h` | 32px | 〃 | Inspector 필드(compact) |
| `--ab-motion` | 160ms | 〃 | hover/selection 전환 |

라이트 값은 `[data-theme="light"] .builder-layout` 에서 재정의한다. 실행 로그 패널은 터미널
성격을 유지해 다크 고정을 허용하되, 그 안의 색도 토큰(`--ab-log-*`)으로 뺀다.

### 5.2 Tool Header

에디터 `.editor-header` 와 같은 높이(56px)·패딩·그림자 없음. 구성:

| 영역 | 요소 | 규칙 |
| --- | --- | --- |
| 좌 | 뒤로(`editor-icon-button`) · 앱 정체(`project-title-btn`: 제목 굵게 + 아래 작은 상태 "저장됨 · 컴포넌트 12 · 노드 3") | 제목 클릭 → 팝오버(제목·설명 편집). ⓘ 버튼·커서 아이콘 제거 |
| 중 | View 탭 `디자인 / 로직 / 코드 / 미리보기` | 세그먼트 1개, 중립 배경, 활성만 `--ab-accent-soft` + 굵게. 로직 탭에 노드 수 배지, 코드 탭에 JS/CSS 존재 점 표시 |
| 우 | 되돌리기·다시 실행 → 실행 로그(배지) → 저장(아이콘, dirty 점) → AI 어시스턴트(에디터와 같은 토글) → **배포**(Primary, Blue) | Green 은 "배포 완료" 모달에서만 |

- "저장 및 배포" → **저장**(아이콘 버튼, 변경 있으면 amber 점)과 **배포**(Primary)로 분리한다.
  둘 다 같은 API(`/api/builder/save`)를 부르지만, 배포만 URL 모달을 연다. 저장은 헤더 상태
  문구를 "저장됨"으로 바꾼다.
- 저장 상태(dirty)는 컴포넌트·노드·스타일의 fingerprint 를 마지막 저장과 비교해 계산한다.
- 생성 방식 세그먼트는 AI 드로어 `controls` 로 이동한다("생성 방식: Blueprint / Code Native").
  뷰 탭을 자동으로 바꾸던 동작은 제거한다.

### 5.3 Palette (240px)

- 상단 검색(32px), 카테고리 소제목(12px, 대문자 아님 — 한국어), 항목 36px: 28px 아이콘 타일
  (`--ab-surface-2`, radius 6) + 이름. hover 시 `--ab-surface-3`, 드래그 핸들 커서.
- 팔레트와 계층 트리는 세로 분할: 팔레트는 내용 높이만큼(최대 55%), 계층은 남은 공간을 채우고
  자체 스크롤. 고정 `max-height: 250px` 제거.
- 계층 항목 28px, 깊이당 14px 들여쓰기 + 얇은 가이드 선, 선택은 `--ab-accent-soft`, 숨김은
  흐리게 + 눈 아이콘 상시 표시.
- 로직 탭의 노드 팔레트: 항목 테두리 색 제거 → 아이콘 타일에만 노드 색. 안내 박스는
  `--ab-surface-2` 카드로.

### 5.4 Canvas

- 워크스페이스 배경 `--ab-bg` + 점 격자(`radial-gradient`, 16px). 격자는 켜고 끌 수 있고 아트보드
  안 격자는 별도 토글(스냅과 무관, 시각 보조).
- 아트보드 위에 **캔버스 툴바**(아트보드 폭에 맞춰 왼쪽 정렬, 32px): 프리셋 세그먼트
  `Desktop | Tablet | Mobile | 직접`, `1024 × 768`(직접 입력 시 편집 가능), `자동 높이` 토글, 격자
  토글. 우측 패널의 "Page (Root) Settings" 에서 크기 관련 항목은 제거하고 배경·여백만 남긴다.
- 아트보드는 `--ab-artboard` 배경, 1px 경계(`--ab-border`), 라이트에서는 그림자 대신 경계로 구분.
- 빈 상태: `EmptyState`(`empty-apps` 일러스트) — 제목 "컴포넌트를 끌어다 놓으세요", 설명 "왼쪽
  팔레트에서 드래그하거나 AI 어시스턴트에게 화면을 설명해 시작할 수 있어요", 행동 1개 "AI 로 시작".
- 미리보기 탭: 같은 아트보드지만 위에 `미리보기 · 상호작용 가능` 배지와 얇은 Green 상단 선을
  둬서 편집 모드와 구분한다. 배포 모달의 Green 과 같은 "실행/결과" 의미다.

### 5.5 Inspector (300px)

```text
┌ [▣] button                      [👁][⧉][🗑] ┐   ← 헤더: 타입 아이콘·이름, 숨김/복제/삭제 아이콘
│ button-3-1724…                      (복사)  │   ← id (monospace, 클릭 복사)
├ ▾ 내용 ───────────────────────────────────┤   ← 섹션: 접기, 상태 기억(localStorage)
│   텍스트          [ Click Me            ]  │
├ ▾ 배치 ───────────────────────────────────┤
│   너비 [180  ] 높이 [45   ]                │   ← 2열, 32px 필드, px 접미 표시
│   X    [40   ] Y    [50   ]                │
│   순서  [⇊][↓][↑][⇈]                       │
├ ▸ 스타일 ─────────────────────────────────┤
│   배경 [■ #3b82f6] 글자 [■ #ffffff]       │   ← 색 필드: 스와치 + hex 텍스트
│   글꼴 크기 [1rem] 굵기 [600 ▾] 정렬 [⋯]   │
│   테두리 [        ] 둥글기 [6px] 여백 [  ] │
│   투명도 ━━━━━━━●━ 100%                    │
│   CSS 클래스 [            ]                │
├ ▾ 동작 ───────────────────────────────────┤
│   클릭 시 [Blueprint ▾]                    │
│   ⓘ Blueprint 트리거 1개 연결됨 → 로직 탭  │   ← 상태 배지, 경고는 amber
```

- 섹션은 `<details>` 가 아니라 버튼 헤더 + 상태(`useState` + localStorage `ab.inspector.sections`)로
  구현한다 — 접힘 애니메이션과 키보드 접근을 제어하기 위해.
- 라벨은 한국어로 통일. 영어 용어는 값에만 남긴다(예: `flex-start`).
- 삭제는 헤더의 아이콘(hover 시 `--ab-danger`)과 섹션 끝의 작은 텍스트 버튼("이 컴포넌트 삭제")
  둘 다 두되, 큰 빨간 블록 버튼은 없앤다.
- 다중 선택 시 Inspector 는 요약(선택 n개, 타입 분포)과 "공통 스타일" 최소 항목만 보이고, 정렬·
  분배는 선택 툴바(§5.6)가 맡는다.
- 아무것도 선택하지 않았을 때: 페이지 설정(배경·여백) + 단축키 안내.

### 5.6 선택 툴바 (플로팅)

에디터 `.editor-selection-toolbar` 와 같은 모양으로 캔버스 하단 중앙(실행 로그 패널이 열리면
그 위로). 2개 이상 선택 시에만 나타난다.

`[n개] │ 왼쪽·가로중앙·오른쪽 │ 위·세로중앙·아래 │ 가로분배·세로분배 │ 너비·높이 맞춤 │ 복제 │ 삭제`

- 다른 부모에 걸친 선택이면 정렬 버튼 비활성 + 툴팁 "같은 컨테이너 안에서만".
- 분배는 3개 이상에서 활성.

### 5.7 실행 로그 패널

- 상단 손잡이·헤더는 유지. 색만 토큰화(`--ab-log-bg`, `--ab-log-text`, 레벨 색 = `--ab-success/
  warning/danger`).
- 헤더에 "자동 열기" 토글을 둔다(지금은 이벤트마다 강제로 열린다).

### 5.8 라이트 테마

`[data-theme="light"] .builder-layout` 에서 §5.1 토큰만 바꾸면 끝나야 한다. 완료 조건: 라이트에서
헤더·팝오버·모달·팔레트·Inspector·캔버스 툴바·선택 툴바가 모두 읽힌다. 실행 로그만 다크 유지.

### 5.9 모바일 (≤ 900px)

- 헤더: 뒤로 · 제목 · [저장][AI][배포]. View 탭은 헤더 아래 한 줄로 내려간다(가로 스크롤).
- 본문: 한 번에 pane 하나. 하단 고정 바 `[컴포넌트] [캔버스] [속성]`(48px, 아이콘 + 라벨).
  컴포넌트를 캔버스에 놓으면 자동으로 캔버스 pane, 컴포넌트를 탭하면 "속성" 배지에 점.
- 캔버스 pane 은 아트보드를 화면 폭에 맞춰 `transform: scale` 로 축소해 **보여주고**, 편집은 탭으로
  선택 → 속성 pane 에서 숫자로 조정하는 흐름을 1차로 한다. Rnd 드래그를 스케일된 부모 안에서
  정확히 동작시키는 것은 2차(좌표 보정 필요).
- 팔레트·속성 pane 은 전체 폭. 선택 툴바는 하단 바 위에 뜬다.

### 5.10 접근성·모션

- 모든 인터랙티브 요소에 `:focus-visible { box-shadow: var(--ab-focus) }`.
- 아이콘 전용 버튼은 `aria-label` + `title`. 툴바 그룹은 `role="toolbar"`.
- 전환은 `--ab-motion`(160ms)로 통일, `prefers-reduced-motion` 에서 0.
- 11px 미만 텍스트 금지(현재 `.builder-log-toggle span` 10px → 11px).

## 8. 피할 것

- 배포된 앱(뷰어)의 컴포넌트 기본 스타일을 이 김에 바꾸는 것 — 사용자가 만든 앱의 모양이
  저장 없이 달라진다.

## 9. 구현 진행 상황 (2026-08-28)

A 단계와 B 단계 1차를 구현했다. 대상: `AppBuilderPage.jsx`, `AppBuilderPage.css`(전면 재작성),
`UIEngine.jsx`(`editorScale` prop).

### 구현한 것

- **토큰**(§5.1): `.builder-layout` 에 `--ab-*` 범위 토큰 선언, `[data-theme="light"]` 재정의.
  CSS 안에서 토큰 블록 밖의 hex 는 Blueprint 노드 카테고리 색(`.palette-tile[data-node]`)만 남았다.
- **Tool Header**(§5.2): 에디터 클래스(`editor-header`, `editor-icon-button`, `project-title-btn`,
  `editor-project-popover`, `editor-field-input`, `assistant-toggle-button`, `btn-run`) 그대로 사용.
  저장(아이콘, dirty 점·Ctrl+S)과 배포(Primary 1개) 분리. 앱 정보는 제목 버튼 팝오버로 통합.
  View 탭 4개(디자인/로직/코드/미리보기) 상시 표시, 로직 탭에 노드 수 배지·코드 탭에 코드 존재 점.
  생성 방식(Blueprint/Global JS)은 AI 드로어 옵션으로 이동.
- **저장 상태**: 저장에 실리는 것만으로 fingerprint 를 만들어 "저장됨 / 저장 안 됨" 표시. ReactFlow 가
  노드에 덧붙이는 `selected`·`measured` 는 제외해 노드 클릭만으로 dirty 가 되지 않게 했다.
- **Palette**(§5.3): 240px, 36px 항목 + 26px 아이콘 타일, 카테고리 소제목, 검색. 팔레트(최대 58%)와
  계층 트리(남은 공간) 세로 분할, 고정 250px 스크롤 제거. 노드 팔레트는 테두리 색 대신 타일 색.
- **Canvas**(§5.4): 캔버스 도구 막대(프리셋·크기·자동 높이·격자·배율), 점 격자 워크스페이스,
  아트보드 격자 토글, `EmptyState` 빈 상태, 미리보기 배지 + Green 상단 선. **폭 맞춤 배율**을
  추가했다 — AI 드로어를 열어 중앙이 좁아지면 아트보드를 축소하고, 같은 배율을 Rnd `scale` 과
  drop 좌표 보정에 넘겨 축소 상태에서도 드래그·리사이즈·드롭이 정확하다. 계획에는 없던 항목이지만
  모바일 pane(§5.9)에 필요한 기반이라 함께 넣었다.
- **Inspector**(§5.5): 헤더(타입 타일·이름·id 복사·숨김/복제/삭제) + 접히는 섹션 5개(내용·배치·
  스타일·동작·표시), 열림 상태 localStorage 기억(`ab.inspector.sections`). 32px 필드, 2열 행,
  색 필드(스와치 + hex), 한국어 라벨. 큰 빨간 삭제 블록 제거 → 헤더 아이콘 + 하단 quiet 버튼.
- **선택 툴바**(§5.6): 다중 선택 시 캔버스 하단 중앙에 뜨는 툴바(정렬 6·분배 2·크기 2·복제·삭제).
  Inspector 는 선택 요약(타입 칩)만 보인다.
- **실행 로그**(§5.7): 토큰화, "자동 열기" 토글(오류는 토글과 무관하게 연다).
- **모바일**(§5.9, 1차): ≤900px 에서 pane 하나만 표시 + 하단 전환 바(컴포넌트/캔버스/속성).
  팔레트 항목을 탭하면 캔버스에 놓고 캔버스 pane 으로 이동. 아트보드는 폭 맞춤 배율로 축소되고
