# 커뮤니티·쪽지 디자인 개선 계획

## 1. 목표

커뮤니티와 쪽지를 별개의 도구가 아니라 **질문에서 관계와 대화로 이어지는 하나의 소셜 경험**으로 정리한다. 기능/API 계약은 유지하면서 정보 위계, 상태 표현, 입력 경험, 반응형 동작을 개선한다.

## 2. 공통 디자인 원칙

- 기존 검정 기반 제품 톤과 파란색 인터랙션 컬러를 유지한다.
- 아바타, 상태 배지, 메타데이터, 둥근 패널의 표현을 두 화면에서 공유한다.
- 제목보다 먼저 사용자가 판단해야 하는 상태(미해결, 해결됨, 읽지 않음, 연결 상태)를 보여준다.
- 빈 화면·로딩·오류·읽기 전용 상태도 완성된 화면으로 설계한다.
- 데스크톱은 넓은 탐색과 읽기 흐름을, 모바일은 한 번에 한 작업만 보이도록 구성한다.
- 모든 클릭 가능한 목록 항목은 키보드로 접근할 수 있고 포커스가 명확해야 한다.

## 3. 커뮤니티

### 정보 구조

1. 소개 헤더: 커뮤니티 목적과 `질문하기` 주 행동
2. 탐색 도구: 미해결·최신·인기·해결됨 세그먼트와 검색
3. 결과 맥락: 현재 정렬 기준, 검색/오류 필터, 결과 수
4. 게시글 카드: 상태 → 제목 → 작성자/태그 → 답변/좋아요 순서
5. 상세: 게시글 → 첨부/워크플로우 → 반응 → 답변 → 답변 작성
6. 작성: 기본 정보 → 본문/첨부 → 워크플로우 공유 → 게시 확인

### 주요 개선

- 미해결 질문을 주황색 대신 제품 파란색 계열 상태로 표시하고 해결됨만 초록색으로 구분한다.
- 텍스트 링크처럼 동작하던 목록 전체를 실제 버튼으로 바꾸고 포커스 상태를 제공한다.
- 작성자 이니셜 아바타와 의미 있는 날짜 표현을 추가한다.
- 목록 로딩에는 스켈레톤, 빈 상태에는 즉시 질문할 수 있는 행동을 제공한다.
- 상세 답변 수, 채택 답변, 작성 폼의 시각적 구획을 강화한다.
- 작성 화면을 섹션 카드로 나누고 입력 도움말·글자 수·필수 조건을 함께 표시한다.

## 4. 쪽지

### 정보 구조

1. 대화 레일: 제목/연결 상태 → 대화 검색 → 새 대화 → 대화 목록
2. 대화 헤더: 상대 아바타/핸들, 1:1 대화 상태
3. 메시지 타임라인: 날짜 구분선, 말풍선, 전송 시각, 내 화면에서 삭제
4. 작성기: 여러 줄 입력, 키보드 안내, 강조된 전송 행동

### 주요 개선

- 대화 목록 검색과 새 대화 열기를 서로 다른 작업으로 분리한다.
- 마지막 메시지, 읽지 않은 수, 최근 시각을 한눈에 비교할 수 있도록 정리한다.
- 새 대화/목록/스레드 로딩과 전송 중 상태를 명확히 보여준다.
- 전송 실패 시 입력을 복원하고 오류를 대화 맥락 안에서 보여준다.
- 720px 이하에서는 목록과 스레드를 동시에 쌓지 않고 선택된 한 화면만 보여준다.
- 모바일 스레드에는 목록으로 돌아가는 버튼을 제공한다.

## 5. 구현 순서

1. 공통 날짜/아바타/상태 표현과 레이아웃 클래스 추가
2. 커뮤니티 목록, 상세, 작성 화면 순서로 마크업과 CSS 개선
3. 쪽지 대화 레일, 타임라인, 작성기와 모바일 전환 구현
4. 키보드 포커스, `aria-live`, 버튼 레이블, 모션 감소 설정 점검
5. 프론트엔드 빌드 및 린트로 회귀 확인

## 6. 완료 기준

- 기존 커뮤니티 게시/답변/좋아요/채택/공유 API가 그대로 동작한다.
- 기존 쪽지 생성/읽음/전송/삭제/SSE 재연결이 그대로 동작한다.
- 360px, 768px, 1280px 폭에서 주요 행동이 가려지거나 이중 스크롤을 만들지 않는다.
- 빈 상태, 로딩, 오류, 읽기 전용, 연결 대기 상태가 모두 구분된다.
- 새 bitmap/WebP 자산 없이 기존 아이콘과 CSS만으로 완성된다.
