# 어드민 운영 콘솔·커뮤니티 검수 통합 계획

## 1. 목표

기존 어드민의 통계·LLM·사용자·피드백을 한 페이지에 길게 나열하던 구조를 역할별 운영 콘솔로 재구성하고, 별도 페이지였던 커뮤니티 검수를 콘솔 안의 핵심 섹션으로 통합한다.

## 2. 권한 원칙

- `admin`: 개요, 커뮤니티 검수, 사용자, LLM 운영, 피드백에 접근한다.
- `moderator`: 커뮤니티 검수에만 접근한다.
- 관리자 전용 API와 검수 API의 서버 권한 판정은 그대로 유지한다.
- moderator가 검수 화면을 열 때 관리자 통계 API를 호출하지 않는다.
- 일반 사용자가 검수 URL에 접근하면 검수 API가 내용을 반환하지 않는다.

## 3. 정보 구조

### 운영 콘솔 공통 셸

1. 콘솔 헤더: 역할, 현재 섹션, 새로고침
2. 섹션 내비게이션: 개요 · 커뮤니티 검수 · 사용자 · LLM 운영 · 피드백
3. 섹션 콘텐츠: URL과 1:1로 대응하여 새로고침과 뒤로가기를 보존

### 개요

- 전체 사용자, 프로젝트, 실행 수, 처리 대기 신고를 주요 지표로 표시한다.
- 로컬 LLM과 커뮤니티 쓰기 상태를 운영 상태 카드로 묶는다.
- 검수, 사용자, LLM 섹션으로 바로 이동하는 빠른 작업을 제공한다.

### 커뮤니티 검수

- 접수·검토 중·쓰기 상태·최근 조치를 상단 요약으로 표시한다.
- 신고 큐는 상태 필터, 대상 미리보기, 신고 사유, 작성자와 조치 버튼 순서로 구성한다.
- 최근 조치 이력은 신고 큐 옆에 배치하여 판단과 감사 추적을 함께 볼 수 있게 한다.
- 쓰기 중지, 콘텐츠 숨김/복구, 7일 정지, 처리/반려 기능은 기존 API를 유지한다.

### 사용자·LLM·피드백

- 사용자는 검색 가능한 표와 인라인 토큰 편집을 제공한다.
- LLM 운영은 성공률·수락률·드라이런·폴백을 주 지표로, 라우팅과 지연을 상세 지표로 분리한다.
- 피드백은 점수와 코멘트가 빠르게 비교되도록 카드형 목록으로 정리한다.

## 4. 라우팅

- `/admin`: 개요
- `/admin/moderation`: 커뮤니티 검수
- `/admin/users`: 사용자
- `/admin/llm`: LLM 운영
- `/admin/feedback`: 피드백
- `/moderation`: `/admin/moderation`으로 이전되는 호환 경로

## 5. 반응형·접근성

- 900px 이하에서는 검수 큐와 조치 이력을 한 열로 전환한다.
- 720px 이하에서는 콘솔 탭을 가로 스크롤로 제공한다.
- 필터와 탭은 `aria-current`/`aria-pressed` 상태를 제공한다.
- 로딩, 빈 상태, 오류, 쓰기 중단 상태는 텍스트와 색을 함께 사용한다.
- 포커스 링과 최소 36px 이상의 주요 클릭 영역을 유지한다.

## 6. 완료 기준

- 관리자와 moderator의 기존 검수 기능이 모두 새 콘솔에서 동작한다.
- moderator 화면에서 `/api/admin/*` 요청이 발생하지 않는다.
- 기존 `/moderation` 링크가 새 검수 섹션으로 이동한다.
- 어드민 섹션별 URL, 로딩, 오류, 빈 상태가 구분된다.
- 프론트엔드 프로덕션 빌드와 변경 파일 ESLint 오류 검사를 통과한다.
