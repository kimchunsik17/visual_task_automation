# 래스터 아트 디렉션 및 캐릭터 바이블

> 작성일: 2026-08-28  
> 적용 범위: `frontend/src/assets/editorial/` 아래 GPT 생성 이미지

## 1. 핵심 방향

기존의 사실적인 3D 제품 광고 스타일 대신 **현대적인 IT 제품용 2.5D 기하학 일러스트**를 사용한다.

- 한 화면에 핵심 오브젝트 3~5개만 둔다.
- 형태는 둥근 사각형, 캡슐, 원, 얇은 연결선처럼 단순화한다.
- 재질은 무광 플라스틱과 평면 색을 기본으로 한다.
- 원근은 약한 등각 또는 정면 2.5D로 고정한다.
- 그라데이션은 입체 구분에 필요한 최소 범위만 사용한다.
- 발광 효과, 유리, 크롬, 과도한 반사, 디테일이 많은 배경을 피한다.
- 설명용 장면은 실제 UI를 흉내 내지 않고 기능의 개념만 추상화한다.
- 이미지 안에 글자, 숫자, 로고, 브랜드 형태를 넣지 않는다.

### 팔레트

| 역할 | 색상 |
| --- | --- |
| 배경 navy | `#0f172a` |
| 표면 slate | `#1e293b`, `#334155` |
| 주 강조 blue | `#3b82f6` |
| 보조 violet | `#8b5cf6` |
| 성공 emerald | `#10b981` |
| 밝은 중립 | `#e2e8f0` |

배경은 단색 또는 아주 약한 명암만 사용한다. 강조색은 한 장당 최대 2개를 주로 사용하고, 세 번째 색은 작은 상태점 정도로 제한한다.

## 2. 고정 캐릭터: 노디(Nodi)

사람이 반드시 필요한 협업, 승인, 완료, 도움말 장면은 실사 인물 대신 노디를 사용한다. 오브젝트만으로 설명 가능한 장면에는 노디를 넣지 않는다.

### 외형

- 역할: 워크플로를 만들고 확인하는 작고 친근한 도우미
- 실루엣: 머리와 몸이 분리되지 않은 세로형 둥근 캡슐 몸체
- 비율: 전체 높이 1.15, 너비 1.0의 짧고 안정적인 비율
- 얼굴: 몸체 상단의 짙은 navy 타원형 화면
- 눈: 작은 하늘색 원 두 개, 간격은 눈 지름 약 1.8개
- 입: 평소에는 없음. 축하·안심 장면에서만 아주 짧은 곡선 하나
- 안테나: 머리 왼쪽 위에서 짧게 올라오며 끝에 emerald 원형 node 하나
- 팔: 짧은 slate 캡슐 두 개, 손가락 없음
- 다리: 짧고 넓은 slate 캡슐 두 개, 신발·발가락 없음
- 몸체 색: blue `#3b82f6`
- 얼굴 화면: navy `#0f172a`
- 눈: pale blue `#e0f2fe`
- 안테나 node: emerald `#10b981`
- 외곽선: 없음
- 재질: 부드러운 무광 플라스틱, 약한 한 단계 음영
- 그림자: 짧고 부드러운 접지 그림자만 사용

### 표정과 포즈

- 기본: 눈 두 개, 입 없음, 팔은 몸 옆
- 확인: 한 팔로 작은 원형 상태점을 가리킴
- 승인: 한 팔로 emerald check token을 들고 있음
- 완료: 양팔을 살짝 들고 작은 미소
- 문제 해결: 몸을 약간 기울이고 violet 조각 하나를 제자리에 끼움

### 금지 변형

- 머리카락, 옷, 안경, 인간형 손가락, 코, 귀를 추가하지 않는다.
- 몸체의 기본 blue와 emerald 안테나 node를 바꾸지 않는다.
- 안테나를 두 개 이상 만들지 않는다.
- 얼굴에 큰 입, 치아, 혀, 볼 터치, 과장된 눈썹을 추가하지 않는다.
- 장면마다 몸 비율이나 팔·다리 개수를 바꾸지 않는다.
- 특정 로봇·게임·애니메이션 캐릭터와 닮게 만들지 않는다.

### 협업 장면의 노디 팀

- 협업을 표현할 때만 동일한 노디를 최대 3명까지 함께 사용할 수 있다.
- 몸체·얼굴·눈·안테나·팔다리 색과 비율은 모두 동일하게 유지한다.
- 역할 구분은 손에 든 작은 token으로만 한다: blue=편집, violet=검토, emerald=승인.
- 몸 색, 얼굴 형태, 안테나 수, 의상으로 역할을 구분하지 않는다.
- 각 캐릭터가 같은 화면에서 서로 다른 포즈를 취하되 크기는 동일하게 유지한다.

## 3. 이미지별 구성 규칙

### 컬렉션 커버

- 16:9, 동일한 카메라 높이와 약한 등각 시점
- 배경은 `#0f172a`, 바닥과 벽의 경계는 보이지 않게 처리
- 좌→우 또는 하단→상단의 단일 흐름만 사용
- 입력, 처리, 결과를 각각 하나의 큰 오브젝트로 단순화
- 노디 사용하지 않음

### Mock 시나리오

- 3:2, 핵심 사물 2~3개와 연결선 하나
- 카드 300px에서도 종류가 구분되는 큰 실루엣
- 실제 서비스 로고와 브랜드 색 조합을 복제하지 않음
- 성공 상태에는 작은 emerald 점 또는 check token 하나만 사용

### 온보딩 완료

- 투명 배경, 중앙에 노디와 연결 완료된 node 3개
- 종이 confetti 대신 작은 원·사각형 6~10개 사용
- 복잡한 광원과 발광 효과 없이 색과 포즈로 축하를 표현

### 보안·credential

- 추상 credential token, 보호막, 승인 gate를 사용
- 자물쇠를 과도하게 크게 만들지 않음
- 노디는 승인 token을 확인하는 포즈로 한 번만 등장

### 포스터 배경

- 세로 3:4 비율, 중앙 60% 또는 상단 45% 중 하나를 텍스트 안전 영역으로 비운다.
- 배경만 생성하며 제목, 본문, 날짜, 가격, 로고 자리를 이미지 안에 그리지 않는다.
- 한 장당 큰 추상 형태 2~4개만 사용한다.
- 사진·인물·제품·UI·아이콘·글자처럼 해석될 수 있는 형상을 피한다.
- 그라데이션은 최대 2색, grain은 거의 보이지 않을 정도로만 사용한다.
- 한글과 CTA는 `posterGeneratorNode`의 HTML/CSS 렌더러가 후처리로 담당한다.

### 랜딩 페이지 서사 장면

- 가로 8:5 또는 3:2 비율, 중앙 65% 안에 하나의 업무 흐름만 표현한다.
- R09 세 장은 동일한 카메라 높이, Nodi 크기, matte 재질을 유지한다.
- 노디는 장면당 최대 1명만 사용하고, 사람의 업무 맥락이 필요하지 않으면 생략한다.
- 실제 제품 캡처나 UI를 흉내 내지 않고 rounded tile, token, gate, path로 개념만 표현한다.
- 국내 업무 자동화는 문서·일정·메시지, AI 오케스트레이션은 분기·조정, 운영 가시성은 상태·관찰의 큰 형태로 구분한다.
- 텍스트가 놓일 한쪽 30~35%에는 작은 오브젝트나 강한 대비를 두지 않는다.

### 릴리스·캠페인 아트

- OG 이미지는 약 1.9:1, 커뮤니티 배너는 3:1 비율을 기준으로 한다.
- 이미지 안에 릴리스명, 날짜, 행사명, CTA, 로고를 직접 생성하지 않는다.
- 실제 문구와 제품 캡처는 이후 HTML/CSS 또는 편집 도구에서 합성한다.
- 릴리스 아트는 하나의 확장되는 workflow motif, 커뮤니티 배너는 최대 3명의 동일한 노디 팀을 사용한다.
- 중앙 또는 좌측에 최소 40%의 카피 안전 영역을 남긴다.

### 마일스톤 애니메이션

- 생성 모델은 투명 노디 키 아트만 담당하고, 움직임·ring·파티클은 CSS로 합성한다.
- PNG 원본은 실제 RGBA인지 검사하며 체크무늬를 배경으로 그린 RGB 결과는 사용하지 않는다.
- Web 배포본은 640×640 투명 WebP를 사용하고 한 장당 약 40KB 이하를 목표로 한다.
- 큰 축하는 최초 달성 시에만 1회 재생하고, 자동으로 2.4~2.9초 안에 닫힌다.
- 여러 완료 이벤트가 겹치면 큐에 넣어 하나씩 재생한다.
- `prefers-reduced-motion: reduce`에서는 bounce·ring·파티클을 제거하고 정적 키 아트만 표시한다.
- 파티클은 cobalt, violet, emerald의 원·둥근 사각형만 사용하며 별·폭죽·종이 confetti는 피한다.

## 4. 일관성 검수표

- [ ] 오브젝트가 5개를 크게 넘지 않는다.
- [ ] 글자·숫자·로고·가짜 UI가 없다.
- [ ] 유리·크롬·네온 효과가 주 표현이 아니다.
- [ ] 한 장에서 강조색이 난잡하게 섞이지 않는다.
- [ ] 300px 폭에서도 주제가 구분된다.
- [ ] 노디의 몸체, 얼굴, 눈, 안테나, 팔다리 수가 바이블과 일치한다.
- [ ] 사람이 필요한 장면에 실사 인물 대신 노디가 사용됐다.
- [ ] 다크 UI에서 이미지 경계가 사라지지 않는다.
