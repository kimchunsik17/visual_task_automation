# Intro 페이지 실험형 조립 캔버스 구현 계획

## 목표

정적인 제품 설명 중심의 기존 소개 페이지를, 방문자가 첫 화면에서 자동화 노드를 직접 조립해 보는
제품 체험형 랜딩으로 바꾼다. 핵심 문장은 “자동화는 보는 것이 아니라 조립하는 것”이며, 인터랙션 자체가
시각적 워크플로우 제품의 설명이 되게 한다.

## 경험 원칙

1. 첫 화면 안에서 노드를 드래그해 배치하고 기존 노드를 다시 움직일 수 있어야 한다.
2. 클릭/탭만으로도 노드를 추가할 수 있어 모바일과 키보드 환경에서 기능이 막히지 않아야 한다.
3. 프리셋을 바꾸면 실제 업무 예시가 즉시 다른 노드 조합으로 나타나야 한다.
4. 실행 버튼은 현재 노드를 순서대로 강조하고 결과 상태를 보여줘 “그림뿐인 캔버스”가 되지 않게 한다.
5. 제품에 없는 기능이나 성과 수치를 꾸며내지 않고, 실제 구현된 승인·로그·자격 증명 기능만 설명한다.

## 정보 구조

1. Sticky header — 제품명, 핵심 섹션 링크, 시작 CTA
2. Interactive hero — 메시지 + 드래그 앤 드롭 조립 캔버스
3. Product thesis strip — 조립, 개입, 관찰이라는 세 가지 제품 원칙
4. Control section — 승인·사전 검사·실행 기록을 코드 기반 미니 시각화로 설명
5. Product evidence — 기존 실제 에디터 WebP 캡처
6. Integrations — 실제 에디터 노드 카탈로그에서 파생한 연동 목록
7. Final CTA + compact footer

## 인터랙션 범위

- 팔레트 노드의 HTML Drag and Drop
- 캔버스 안 기존 노드 재배치
- 팔레트 클릭 시 빈 위치 자동 추가
- 노드 개별 삭제 및 전체 초기화
- 업무 프리셋 3종 전환
- 좌→우 순서의 실행 시뮬레이션과 완료 피드백
- `prefers-reduced-motion` 및 키보드 포커스 대응

## 이미지 정책

- 새 히어로 WebP는 만들지 않는다. 조립 캔버스가 히어로 비주얼을 대신한다.
- 제품 증거 섹션은 기존 `demo-1.webp`를 사용한다.
- 향후 고객 사례/브랜드 캠페인 섹션을 추가할 때만 별도 WebP 슬롯을 만든다.

## 검증

- `npm run build`
- 데스크톱과 모바일 브라우저 렌더링 확인
- 노드 추가·재배치·삭제·프리셋·실행 동작 확인
- 콘솔 오류 및 가로 스크롤 여부 확인
